# Aidemy

> Aidemy is a free, open-source agent skill and an alternative to Udemy and Coursera. Give it a topic and it researches the web, compares what good sources agree on, and builds a course of two-host audio lessons of 2 minutes each, with a one-screen card, one small practice and links to its sources. MIT licensed. This fork runs the work in a Docker container, writes lessons in Russian and synthesises audio locally with Piper, Kokoro-ru and Silero v5: no paid voice service and no API key anywhere in the fork.

Installing the fork: copy `skills/aidemy/` into your agent's skills directory (`~/.qoder/skills/aidemy/` for Qoder Desktop, `~/.claude/skills/aidemy/` for Claude Code), then ask "teach me <topic>". Upstream installs differently, through its plugin and the `claudemy.skill` file from its v0.2.0 release: that is its install path, not the fork's.

Key facts:
- Addresses: origin `https://github.com/bahooo22/aidemy`, upstream `https://github.com/assafkip/claudemy`. The fork repository was renamed from `bahooo22/claudemy` on 2026-10-26; GitHub redirects the old address, but every file in the fork now uses the new one.
- Scripts run inside the container: `docker compose exec -T aidemy python skills/aidemy/scripts/<script>.py ...` from the repository root.
- Output: about 12 MP3 lessons of 2 minutes, a card per lesson, a playbook of rules, and a lesson plan showing where sources disagree.
- Research: 20 to 40 pages per topic, at most 3 per site; every lesson citation is checked against pages the course actually read.
- The gate `check_lessons.py` fails a citation to a page that is not in `raw/` and holds the word corridor per engine: 300–339 words on Piper, 280–350 on Silero, 250–313 on Kokoro. The Piper ceiling comes from voiced lessons (up to 0.443 s per word — the pauses between turns are inside the duration), not from the lab fixture.
- Narration style is part of the input: `"style": {"preset": "менторский", "note": "..."}` in `sources.json`; six presets in `references/style-briefs.md`, four tone examples each.
- Audio is local and offline. Models: Piper 121 MiB per pair, Kokoro 635 MiB, Silero 141 MiB. Measured on this machine: eleven host pairs in the CPU container took 4.8–36.7 s for a six-turn fixture (22–25 s of audio); Kokoro on `cuda` took 25.6 s against 36.7 s on `cpu`, and the first run inside a freshly started GPU container took 211.7 s because 312 MiB of checkpoints move to VRAM.
- Web run: the `aidemy-web` service, host port 8090 (always 8080 inside the container), entered with the access code `AIDEMY_WEB_TOKEN` from `.env`: 403 without it, and the page then shows a field "Access code" with an "Enter" button; the code lives in a cookie for 30 days. The form asks in plain words: "What should it teach?", "How should it sound?" (six presets plus a free-text field), "How many lessons?" (1 to 12, 3 by default). Voices and pitch are folded under "Voices and sound (optional)", together with "let one person speak", and the launch button is "Make the course". The section "Listen to the voices" with the "Play the sample" button carries the line "Twenty seconds of the chosen pair talking. No course starts." and serves exactly that as MP3; the request list is headed "My courses". A request moves through the statuses "queued / topic map / reading / writing / voicing / done / error". The runner is `AIDEMY_RUNNER=auto|api|local|qoder`. The topic box opens pre-filled with a random topic out of eight in the page language and clears it on focus unless the text was edited by hand. The job page `/job/<n>` shows a "Lessons" block: each lesson gets an `<audio controls preload="none">` player pointing at `/files/<slug>/class/<lesson folder>/<file>.mp3` and the `card.md` card rendered to HTML by a tiny renderer (`#`, `##` and `###` become headings, `- ` lines make a list, `**…**` is bold, and HTML is escaped first), so a phone reads the card without downloading it. "My courses" is a form: a checkbox per request, "select all", and a "Delete the marked ones" button behind the confirmation "Delete the marked courses together with their files?"; deleting removes the request and its journal rows from the `jobs` and `events` tables and wipes the course folder from disk, while a hand-edited slug that is not a direct child of the root loses only the queue rows.
- Journal and recovery: every status or message change is written as a row into the `events` table of the same `queue.db`, and the job page shows the last twelve steps with their times; after a service restart, jobs that were shown as "writing" or "voicing" get the error «прогон прерван перезапуском сервиса» — journal messages themselves stay Russian in both languages, because the pipeline writes them, while the page heading under a failed job reads "Something went wrong. Read the last journal line."; the queue and the jobs waiting for an agent are left alone. A request parked in "topic map" on the `api` or `local` branch does not sit there until someone presses a button: the tick re-checks up to three parked requests every five seconds (oldest by update time first) and moves them on once `raw/` holds three pages or the local model comes up (`lms server start`, then `lms load`); when the answer has not changed, the status and the message are not rewritten, so the journal does not grow every five seconds, and jobs with `runner=qoder` are deliberately left out of that re-check. A model call lasts up to 900 seconds (`AIDEMY_LLM_TIMEOUT`), and each page enters the prompt trimmed to 1800 characters. The `api` branch is the only one leaving the machine and it stays off without `AIDEMY_LLM_API_KEY`: `local` by default, otherwise `qoder`. A course can also be erased from the page: in "My courses" every request has a checkbox, "select all" sits above the list, and the "Delete the marked ones" button asks "Delete the marked courses together with their files?" and removes the request and its journal rows from `queue.db` together with the course folder on disk; a request whose folder path was edited by hand and is not a direct child of the courses root loses only the queue rows, and its files stay.
- Morning checklist: `docs/index.html` has a section "Утро: как показать курс с телефона" - the home-network address of the page, the access code, the run, how to play the lessons right on the page and how to take the files with you. The page answers 403 without the access code from `.env`; only the `/health` endpoint stays open.
- Requires: Docker Desktop (the image carries Python 3, beautifulsoup4 and ffmpeg) and an agent with web search.
